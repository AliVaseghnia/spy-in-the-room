# Spy Game Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a no-build, same-device Spy party game that is playable by 4 to 12 friends in one browser session.

**Architecture:** A semantic `index.html` shell is styled by `styles.css` and driven by `game.js`. Pure game rules live in `game-logic.js`, which is available both as `window.SpyGameLogic` in the browser and as a CommonJS module for Node's built-in test runner. The controller owns only UI state, event wiring, focus, and the single timer lifecycle; it never re-implements rule outcomes.

**Tech Stack:** HTML5, CSS3, vanilla JavaScript, Node.js built-in `node:test` and `node:assert` only. No package install, framework, external font, image, or network request.

**Spec:** `1 Projects/Spy game/docs/superpowers/specs/2026-09-06-spy-game-design.md`

## Global Constraints

- Support 4 to 12 trimmed, unique player names and reject empty or duplicate names.
- Deal one spy for 4 to 8 players and two spies for 9 to 12 players.
- Keep the five visible phases exactly `setup`, `reveal`, `round`, `accuse`, and `result`.
- Use a local location deck with at least 20 locations; no network or third-party dependency is allowed.
- Make `game-logic.js` pure and testable in Node while exposing it as `window.SpyGameLogic` in the browser.
- Use one dark theme, one amber accent, one soft radius scale, `min-height: 100dvh`, visible focus rings, `prefers-reduced-motion`, and no em-dashes in visible page copy.
- Every phase needs an actionable primary control, every input needs a visible label, and dynamic phase changes need an `aria-live` announcement.
- Preserve the timer invariant: at most one interval is active, and it is cleared whenever the phase leaves `round`.

### Task 1: Pure rules engine and executable tests

**Files:**
- Create: `1 Projects/Spy game/game-logic.js`
- Create: `1 Projects/Spy game/test/game-logic.test.js`

**Interfaces:**
- `validatePlayers(rawNames)` returns `{ ok: boolean, names: string[], error: string }`.
- `getSpyCount(playerCount)` returns `1` for 4 through 8 and `2` for 9 through 12; it throws for other counts.
- `shuffle(items, random = Math.random)` returns a new shuffled array and never mutates `items`.
- `dealRound(names, location, random = Math.random)` returns `{ location, spies: string[], cards: Array<{ player: string, isSpy: boolean, location: string | null, category: string | null }> }`.
- `formatTime(totalSeconds)` returns `MM:SS` with both fields zero-padded and clamps negative input to `00:00`.
- `resolveAccusation(accusedPlayer, spies)` returns `{ phase: 'spy-guess' }` when the accused player is a spy, otherwise `{ phase: 'result', winner: 'spies', reason: 'wrong-accusation' }`.
- `resolveSpyGuess(guess, location)` returns `{ winner: 'spies', reason: 'correct-guess' }` or `{ winner: 'group', reason: 'wrong-guess' }`.
- `LOCATION_DECK` is an exported array of at least 20 `{ name, category }` objects with unique names.

**Implementation notes:**

- Keep the module dependency-free. Use a small UMD-style footer so Node can `require()` it while the browser receives `window.SpyGameLogic`.
- `dealRound` should shuffle the names before choosing the first `spyCount` names, then create cards in the original roster order so the reveal screen can remain predictable.
- Non-spy cards contain the selected location and category. Spy cards contain `null` for both.
- Do not put DOM calls, timers, dates, or mutable global game state in this file.

### Task 3: Browser controller and complete game flow

**Files:**
- Create: `1 Projects/Spy game/game.js`

**Interfaces:**
- `game.js` consumes `window.SpyGameLogic` and the stable HTML IDs from Task 2.
- The controller keeps one state object with `{ phase, players, timerSeconds, round, revealIndex, secondsLeft, accusedPlayer, accusation, winner }`.
- `render()` hides all five view sections, then shows the section named by `state.phase` and updates the `aria-live` announcement text.
- `startRound()` validates setup, deals a round, sets `phase = 'reveal'`, and focuses the current reveal action.
- `beginTimer()` creates at most one interval and uses `clearInterval` before creating a new one.
- `finishRound()` clears the interval and moves to `accuse`.
- `resetForReplay()` retains the normalized roster and timer selection but generates a new round and returns to `reveal`.

**Implementation notes:**

- Wire setup submission to `validatePlayers`. Render an inline error message for fewer than four names, duplicates, or more than twelve names. Do not rely on an HTML validity bubble as the only error.
- The reveal screen starts with the player's name visible and the secret hidden behind a button. After reveal, replace the primary action with `Hide card and pass`; hiding the card must clear the secret text before advancing.
- Keep the location hidden during the round. The round view may show only `Round in progress`, the timer, and a rule reminder.
- When the timer hits zero, render the accuse view exactly once and announce that time is up.
- In accuse view, create one accessible button per player. After selecting a suspect, call `resolveAccusation`. A wrong accusation goes straight to result. A correct accusation renders the location deck as buttons for the spy guess.
- In result view, display explicit winner copy, the location, and a list of all spies. The group and spies must be identifiable in text, not only through color.
- Use a tiny focus helper that calls `.focus()` after each phase change. Avoid focus traps because there is no modal dialog.
- Add CSS class changes only for feedback, and remove timers/listeners in a single `stopTimer()` path.
